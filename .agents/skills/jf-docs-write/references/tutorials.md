# Tutorials

A tutorial teaches by having the reader build one small, real thing from start to
finish. The reader is new and learning; the goal is a working result and the
confidence to continue, not complete coverage.

## Structure

1. One or two sentences on what the reader will build, with a picture or the
   finished code's output when it helps.
2. Prerequisites: what to install and know first, linked.
3. Numbered steps. Each step produces something the reader can run or see.
4. The finished result, in full.
5. What to read next: usually the explanation of the concepts used, then the
   guides for common tasks.

## Rules

- Choose one path and stay on it. Don't offer alternatives mid-tutorial; mention
  them at the end.
- Explain only what the current step needs. Link to an explanation for the rest.
- Keep every step runnable. The reader should never write code they can't run
  until three steps later.
- Introduce one concept at a time, in the order the reader meets it.
- Use the same example domain throughout, and keep it realistic.
- Test the whole tutorial from a fresh project when possible. A broken step ends
  the tutorial for the reader.
